Suzuki-Kasami (token)

One token exists. Whoever holds it may enter the critical section (CS).

  1. A process without the token raises its request number and sends REQUEST to everyone.
  2. Each process remembers the highest request number it saw from every other process (RN).
  3. The token records the last served request of each process (LN) and a queue of waiting processes.
  4. On leaving the CS, the holder adds every process with RN = LN + 1 to the queue and sends the token to the first one.

Cost: N messages per entry (N-1 REQUEST + 1 TOKEN), or 0 if the process already holds the token.

Ricart-Agrawala (replies)

No token. A process needs permission from everybody else.

  1. The process stamps its request with a logical clock and sends REQUEST to everyone.
  2. A receiver replies at once, unless it is in the CS or its own waiting request has the smaller (time, id).
  3. In those two cases it keeps the reply back until it leaves the CS.
  4. With N-1 replies the process enters the CS.

Cost: 2(N-1) messages per entry, always.
